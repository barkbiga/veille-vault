### 🔥 4.5/5 — API Security
**[6 Ways to Give AI Agents Deterministic API Context](https://nordicapis.com/6-ways-to-give-ai-agents-deterministic-api-context/)**  
_Nordic APIs • 2026-04-30_

PayPal découvre que ses AI coding assistants utilisent systématiquement des APIs obsolètes. Thoughtworks crée un framework avec instruction files versionnés pour migrer 25+ APIs. 6 stratégies : Agent Skills, Deterministic Chains, Context Plugins, Ruleset Engineering, **MCP (Model Context Protocol)**, Structured Outputs. MCP émerge comme standard pour fournir contexte déterministe aux agents.

**💡 Insight** : Le problème n'est pas "comment authentifier un agent" mais "comment garantir qu'il appelle la bonne API de la bonne façon". MCP pourrait devenir aussi structurant que OAuth.

**📝 Opportunité éditoriale** : 7/10 — "L'IA ne raisonne pas, elle devine — et vos APIs sont trop complexes pour être devinées"

### 🔥 4.5/5 — Architecture • ⚠️ Vendor
**[Cut AI token usage by 96%? Here's how AWS Strands Agents does it](https://thenewstack.io/strands-agents-tool-design/)**  
_The New Stack • 2026-04-29_

Demo AWS Strands : (1) Direct API mapping (1 endpoint = 1 tool) → 52k tokens. (2) Intent-based tools (outcome-driven) → 2k tokens (**96% réduction**). (3) MCP + semantic search → divise encore par 2. Principe : "Agents étroitement scopés > agents génériques". Moins de tools exposés = moins d'erreurs.

**💡 Insight** : Intent-based tools = microservices pattern appliqué aux agents. Chaque agent = bounded context. 96% de réduction tokens change l'équation économique pour agents banking en prod.

**📝 Opportunité éditoriale** : 6/10 — "Pourquoi exposer 16 APIs à votre agent est une erreur — même si elles sont toutes pertinentes"

### ⭐ 4.0/5 — Architecture
**[LLM 0.32a0 is a major backwards-compatible refactor](https://simonwillison.net/2026/Apr/29/llm/#atom-everything)**  
_Simon Willison • 2026-04-29_

Refactorisation majeure de la bibliothèque LLM : passage de `prompt → response text` à `messages[] → streaming parts[]`. Motivations : gérer conversations complètes (pas juste build from scratch) + outputs hétérogènes (texte + reasoning + tool calls + images + tool outputs serveur-side). Abstraction critique pour diversité modèles frontier.

**💡 Insight** : Les abstractions initiales (`prompt → text`) ne scalent pas. Leçon pour APIs bancaires : anticiper l'évolution, pas juste le cas actuel. Streaming parts = composabilité.

### ⭐ 3.5/5 — Gouvernance • 🔄 Contrarian
**[The Zig project's rationale for their firm anti-AI contribution policy](https://simonwillison.net/2026/Apr/30/zig-anti-ai/#atom-everything)**  
_Simon Willison • 2026-04-30_

Zig bannit toute contribution générée par LLM. Rationale Loris Cro : les projets open source investissent dans les *contributeurs*, pas les *contributions*. Chaque PR = "contributor poker" — pari sur l'humain long-terme. LLM casse ce modèle : PR parfaite ≠ confiance construite. Conséquence : Bun (acquis par Anthropic, développé en Zig) ne peut pas upstreamer ses optimisations 4x car générées par IA.

**💡 Insight** : Si Zig (systèmes critiques) bannit l'IA et que ça fonctionne, ça valide un modèle alternatif pour secteurs régulés (banking, santé). Les agents cassent les mécanismes de construction de confiance progressive (≠ Zero Trust).

**📝 Opportunité éditoriale** : 8/10 — "La gouvernance est un pari sur les humains, pas sur le code"
